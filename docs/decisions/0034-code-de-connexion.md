# 0034 — Un code à 6 chiffres avec le lien de connexion

- **Contexte** : sur iPhone, l'appli installée sur l'écran d'accueil a ses propres cookies, à part de Safari. Le lien reçu par courriel s'ouvre dans Safari : il connecte Safari, pas l'appli installée. Une appli installée déconnectée (90 jours sans usage, « tous mes appareils », suspension levée) ne pouvait revenir qu'en la supprimant puis en la réinstallant.
- **Options** : (1) expliquer le détour (supprimer, réinstaller) ; (2) **un code à 6 chiffres dans le même courriel que le lien**, à taper sur la page de connexion de l'appli ; (3) un mot de passe ou une clé d'accès (passkey).
- **Choix** : (2), avec le plugin `emailOTP` de Better Auth (déjà dans la dépendance, rien de nouveau à installer). Le lien seul marche toujours.
- **Mêmes garanties que le lien** : adresses autorisées seulement ; un courriel par minute et par adresse (la réservation du lien couvre le code, créé seulement si le courriel part) ; même réponse que l'adresse soit connue ou non ; valable 5 minutes ; usage unique ; **3 essais** par code, puis il faut un nouveau courriel. En base, une empreinte du code liée au secret de l'appli (HMAC) : une simple empreinte se retrouverait en essayant le million de codes. Un nouveau courriel remplace l'ancien code. Si le courriel ne part pas, lien et code sont effacés. Suspension, départ ou changement d'adresse effacent aussi le code.
- **Lien et code du même courriel** : le code utilisé efface le lien. Le lien utilisé laisse le code valable jusqu'à ses 5 minutes : sur iPhone, l'agent qui appuie sur le lien connecte Safari et doit encore taper le code dans l'appli installée ; et un antivirus de messagerie qui ouvre le lien ne doit pas griller le code. Au pire, deux sessions, toutes deux par la personne qui a le courriel.
- **Routes fermées** : toutes les routes HTTP du plugin (connexion par code, envoi d'un code seul, vérification d'adresse, mot de passe oublié, changement d'adresse) sont fermées (`disabledPaths`). Le code ne passe que par l'action de la page de connexion.
- **Un seul message de refus** : code faux, expiré ou trop d'essais disent la même chose (« Ce code ne marche pas : il est faux, a expiré (5 minutes) ou a déjà eu 3 essais… »). Les distinguer dirait qu'un code existe, donc que l'adresse est autorisée.
- **Limites connues** :
  - deviner un code : au plus 3 essais par courriel et un courriel par minute, soit environ 0,4 % de chances par jour d'acharnement contre une adresse (au plus 300 courriels par jour avec l'offre gratuite de Brevo, soit environ 0,1 %). Chaque essai envoie un courriel à l'agent visé, qui le remarquerait. Parade possible, non faite : au-delà de quelques codes grillés en 24 h, le courriel part avec le lien seul ;
  - un faux code prend un peu plus de temps quand un code existe : mesurable seulement après avoir fait partir un courriel vers l'adresse visée.
- **Validé par** : le porteur (le besoin et le code dans le même courriel). Choix de Claude, à valider : 3 essais ; un seul message de refus ; pas de plafond quotidien des codes grillés ; le lien utilisé ne grille pas le code ; le code dans le texte du courriel et non dans son objet (il serait lu sur l'écran verrouillé).
