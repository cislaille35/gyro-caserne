# 0036 — Le journal de Cloudflare (Workers Logs)

- **Contexte** : le relevé quotidien compte les coupures (erreur 1102) et les erreurs par Worker, sans dire quelle page est en cause. Le journal de Cloudflare, Workers Logs, le dit : il garde chaque requête (adresse de la page, réponse, temps de calcul) et ce que l'appli écrit à la console. Vérifié dans la documentation de Cloudflare le 15/11/2026 :
  - **offre gratuite** : 200 000 événements par jour, gardés 3 jours ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)). À partir du 1er décembre 2026 : 0,5 Go par jour, gardés 7 jours ; au-delà, Cloudflare n'enregistre plus rien jusqu'à minuit UTC, sans rien facturer ([tarifs Observability](https://developers.cloudflare.com/observability/pricing/)). Nos deux Workers font quelques centaines de requêtes par jour : très loin de la limite ;
  - **temps de calcul** : la documentation ne dit pas que le journal en coûte. Le seul coût est celui de nos `console.*`, rares (erreurs seulement) ;
  - **lieu** : « sans frontière de métadonnées, les journaux peuvent être stockés dans les centres de données de Cloudflare partout dans le monde » ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)). Cette frontière (Customer Metadata Boundary, Union européenne ou États-Unis) fait partie de la Data Localization Suite, **réservée à l'offre Enterprise, en option payante** ([Data Localization](https://developers.cloudflare.com/data-localization/)), et n'est pas prise en charge pour les Workers en `workers.dev` ([compatibilité](https://developers.cloudflare.com/data-localization/compatibility/)). Sur l'offre gratuite, **le journal peut donc sortir de l'Union européenne**, contrairement aux bases D1 (juridiction `eu`) ;
  - **activé d'office** : « tous les Workers créés récemment ont le journal activé par défaut » ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/), [configuration Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/)). `gyro-caserne-laille`, créé le 12/11/2026 sans réglage `observability`, l'a donc probablement déjà, comme la préprod ;
  - **contenu** : chaque requête est enregistrée avec sa méthode et son adresse, paramètres compris, et ses en-têtes ; Cloudflare dit masquer les en-têtes sensibles (`Authorization`, `Cookie`…) ([billet de Cloudflare](https://blog.cloudflare.com/introducing-workers-dashboard-logs)), sans détail pour les paramètres d'adresse.
- **Ce qui partirait de l'appli** (relu le 15/11/2026) :
  - les erreurs passées brutes à la console : une erreur de requête de Drizzle recopie ses valeurs (`params: …`, adresses e-mail, noms), Brevo ou Better Auth peuvent citer l'adresse ; SvelteKit écrit aussi toute erreur imprévue ;
  - sans `BREVO_CLE`, le courriel de connexion entier (adresse, lien et code) : avec un journal gardé, il serait lisible après coup ;
  - dans l'adresse des pages : le jeton du lien de connexion (`/api/auth/magic-link/verify?token=…`, usage unique, 5 minutes) et la clé du lien d'agenda (`/agenda/<clé>.ics`, **valable tant que l'agent ne la change pas**). Ces deux-là, Cloudflare les enregistre de lui-même : l'appli n'y peut rien, sauf couper les journaux de requêtes (`invocation_logs: false`), ce qui retire aussi la page en cause d'une coupure.
- **Choix** :
  1. **rien de personnel écrit par l'appli** : toute erreur passe par `resumeErreur` (socle), qui garde le nom, le message sans adresse, lien, jeton ni valeurs de requête, la cause et la pile. `handleError` et le journal de Better Auth font de même. Un test refuse une erreur passée brute à la console ;
  2. **plus jamais de courriel au journal en ligne** : sans `BREVO_CLE`, le courriel n'est écrit à la console que si l'appli tourne en local (`BETTER_AUTH_URL` sur `localhost`) ; en ligne, l'envoi échoue. Un centre d'essai en ligne a donc besoin de Brevo, comme le contrôle après déploiement l'exigeait déjà ;
  3. **préprod (données fictives) : journal gardé**, requêtes comprises (`observability` dans `centres/exemple/wrangler.jsonc`, `head_sampling_rate: 1`, `invocation_logs: true`). Le relevé quotidien y ajoute coupures et erreurs par page ;
  4. **production : journal coupé, écrit en toutes lettres** (`"observability": { "enabled": false }` dans `centres/laille/wrangler.jsonc`), puisqu'il peut sortir de l'Union européenne. Prend effet au prochain tag ; pour couper tout de suite : tableau de bord Cloudflare › Workers & Pages › `gyro-caserne-laille` › Settings › Observability. **Au porteur de trancher** s'il veut le garder, et comment :
     - (a) coupé (choix actuel) : rien hors de l'Union européenne, pas de page en cause en production ;
     - (b) gardé sans les requêtes (`invocation_logs: false`) : seulement nos messages d'erreur, nettoyés ; pas d'adresse de page, donc pas de clé d'agenda ;
     - (c) gardé en entier, comme la préprod : la page en cause de chaque coupure, mais les adresses (clé d'agenda comprise) restent 3 à 7 jours chez Cloudflare, peut-être hors de l'Union européenne ;
  5. **chaque centre dit lui-même** s'il garde le journal (test de `centres.test.ts`), puisque Cloudflare l'active d'office.
- **Relevé quotidien** : l'API de requête du journal ([Telemetry query](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/)) demande le droit **« Workers Observability » en écriture** sur le jeton `CLOUDFLARE_API_TOKEN` (c'est le seul droit que Cloudflare accepte pour lire, même pour une simple requête). Sans lui, le relevé le dit et continue. Le résumé est public : chemins génériques (`/agents/:id`) et nombres seulement.
- **Validé par** : à valider par le porteur (choix de Claude : 1, 2, 3, 5, et la production coupée en attendant sa décision).
