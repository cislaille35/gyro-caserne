# 0036 — Le journal de Cloudflare (Workers Logs)

- **Contexte** : le relevé quotidien compte les coupures (erreur 1102) et les erreurs par Worker, sans dire quelle page est en cause. Le journal de Cloudflare, Workers Logs, le dit : il garde chaque requête (adresse de la page, réponse, temps de calcul) et ce que l'appli écrit à la console. Vérifié dans la documentation de Cloudflare le 15/11/2026 :
  - **offre gratuite** : 200 000 événements par jour, gardés 3 jours ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)). À partir du 1er décembre 2026 : 0,5 Go par jour, gardés 7 jours ; au-delà, Cloudflare n'enregistre plus rien jusqu'à minuit UTC, sans rien facturer ([tarifs Observability](https://developers.cloudflare.com/observability/pricing/)). Nos deux Workers font quelques centaines de requêtes par jour : très loin de la limite ;
  - **temps de calcul** : la documentation ne dit pas que le journal en coûte. Le seul coût est celui de nos `console.*`, rares (erreurs seulement) ;
  - **lieu** : « sans frontière de métadonnées, les journaux peuvent être stockés dans les centres de données de Cloudflare partout dans le monde » ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)). Cette frontière (Customer Metadata Boundary, Union européenne ou États-Unis) fait partie de la Data Localization Suite, **réservée à l'offre Enterprise, en option payante** ([Data Localization](https://developers.cloudflare.com/data-localization/)), et n'est pas prise en charge pour les Workers en `workers.dev` ([compatibilité](https://developers.cloudflare.com/data-localization/compatibility/)). Sur l'offre gratuite, **le journal peut donc sortir de l'Union européenne**, contrairement aux bases D1 (juridiction `eu`) ;
  - **activé d'office** : « tous les Workers créés récemment ont le journal activé par défaut » ([Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/), [configuration Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/)). `gyro-caserne-laille`, créé le 12/11/2026 sans réglage `observability`, l'a donc probablement déjà, comme la préprod ;
  - **contenu** : chaque requête est enregistrée avec sa méthode et son adresse, paramètres compris, et ses en-têtes ; Cloudflare dit masquer les en-têtes sensibles (`Authorization`, `Cookie`…) ([billet de Cloudflare](https://blog.cloudflare.com/introducing-workers-dashboard-logs)), sans détail pour les paramètres d'adresse.
- **Ce qui partirait de l'appli** (relu le 15/11/2026) :
  - les erreurs passées brutes à la console : une erreur de requête de Drizzle recopie ses valeurs (`params: …`, adresses e-mail, noms), Brevo ou Better Auth peuvent citer l'adresse ; SvelteKit écrit aussi toute erreur imprévue ;
  - sans `BREVO_CLE`, le courriel de connexion entier (adresse, lien et code) : avec un journal gardé, il serait lisible après coup ;
  - dans l'adresse des pages : le jeton du lien de connexion (`/api/auth/magic-link/verify?token=…`, usage unique, 5 minutes) et la clé du lien d'agenda (`/agenda/<clé>.ics`, **valable tant que l'agent ne la change pas**). Ces deux-là, Cloudflare les enregistre de lui-même : l'appli n'y peut rien, sauf couper les journaux de requêtes (`invocation_logs: false`), ce qui retire aussi la page en cause d'une coupure.
- **Choix** :
  1. **rien de personnel écrit par l'appli** : toute erreur passe par `resumeErreur` (socle), qui garde le nom, le message sans adresse, lien, jeton ni valeurs de requête, la cause et la pile. `handleError`, le journal de Better Auth et les tâches en arrière-plan ou planifiées (rattrapées : sinon Cloudflare écrirait lui-même l'erreur brute) font de même. Un test n'accepte à la console que des arguments sûrs ;
  2. **plus jamais de courriel au journal en ligne** : sans `BREVO_CLE`, le courriel n'est écrit à la console que si l'appli tourne en local (`BETTER_AUTH_URL` sur `localhost`) ; en ligne, l'envoi échoue. Un centre d'essai en ligne a donc besoin de Brevo, comme le contrôle après déploiement l'exigeait déjà ;
  3. **préprod (données fictives) : journal gardé**, requêtes comprises (`observability` dans `centres/exemple/wrangler.jsonc`, `head_sampling_rate: 1`, `invocation_logs: true`). Le relevé quotidien y ajoute coupures et erreurs par page ;
  4. ~~**production : seulement nos messages, sans le journal des requêtes**~~ (abandonné le 15/11/2026 pour le choix (a), voir la révision plus bas) (`"observability": { "enabled": true, "head_sampling_rate": 1, "logs": { "invocation_logs": false } }` dans `centres/laille/wrangler.jsonc`), choix (b) du porteur le 15/11/2026. Prend effet au prochain tag. **À faire dès maintenant** dans le tableau de bord (Workers & Pages › `gyro-caserne-laille` › Settings › Observability) : couper le journal, sans doute actif depuis le 12/11 avec les erreurs brutes d'avant ce lot. Les trois choix étaient :
     - (a) coupé : rien hors de l'Union européenne, pas de page en cause en production ;
     - **(b) retenu** : gardé sans les requêtes (`invocation_logs: false`) : seulement nos messages d'erreur, nettoyés ; pas d'adresse de page, donc pas de clé d'agenda. Le relevé ne donne donc pas la page en cause d'une coupure en production ;
     - (c) gardé en entier, comme la préprod : la page en cause de chaque coupure, mais les adresses (clé d'agenda comprise) restent 3 à 7 jours chez Cloudflare, peut-être hors de l'Union européenne ;
  5. **chaque centre dit lui-même** s'il garde le journal (test de `centres.test.ts`), puisque Cloudflare l'active d'office.
- **Relevé quotidien** : l'API de requête du journal ([Telemetry query](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/)) demande le droit **« Workers Observability » en écriture** sur le jeton `CLOUDFLARE_API_TOKEN` (c'est le seul droit que Cloudflare accepte pour lire, même pour une simple requête). Sans lui, le relevé le dit et continue. Le résumé est public : chemins génériques (`/agents/:id`) et nombres seulement.
- **Validé par** : le porteur, le 15/11/2026 (production : choix (b)).
- **Suite** : [0037](0037-page-au-journal.md) ajoutait en production une ligne par requête, le nom générique de la page, pour que le relevé nomme la page d'une coupure.

## Révision du 15/11/2026 (soir) : production coupée, choix (a)

- **Preuve** (essai du porteur sur la préprod, journal des requêtes coupé, `invocation_logs: false`) : **chaque ligne écrite par l'appli** porte quand même l'adresse de la requête, `$workers.event.request.url`, `.path` et les paramètres (`$workers.event.request.search.*`), sans IP ni en-têtes. Et ces lignes ne portent **pas** l'issue de la requête : `$workers.outcome` n'existe que sur l'événement de requête de Cloudflare (`cf-worker-event`).
- **Conséquences** : le choix (b) gardait l'adresse complète (clé d'agenda comprise, dans le chemin `/agenda/<clé>.ics`) de toute ligne écrite en production ; la ligne « Page » de la 0037 en aurait écrit une **par requête**, sans pouvoir nommer une coupure (pas d'issue). `redact_query_string` ne retire que la partie `?…`, pas le chemin : il ne suffit pas.
- **Choix du porteur** :
  1. **production (`centres/laille/wrangler.jsonc`) : tout coupé**, choix (a) : `"observability": { "enabled": false, "logs": { "enabled": false, "invocation_logs": false }, "traces": { "enabled": false }, "issues": { "enabled": false } }`. En toutes lettres, journal, traces et détection des problèmes, puisque Cloudflare active le journal d'office (« par défaut à `true` pour tous les nouveaux Workers », [configuration Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/)) et que la détection se coupe au déploiement suivant si la clé manque ([Issues](https://developers.cloudflare.com/workers/observability/issues/)). Rien de la production n'est gardé chez Cloudflare ; `wrangler tail` (en direct, rien de gardé) reste possible ;
  2. **préprod (`centres/exemple/wrangler.jsonc`) : tout gardé**, requêtes comprises, **plus les traces** (`"traces": { "enabled": true, "head_sampling_rate": 1 }`) **et la détection des problèmes** (`"issues": { "enabled": true }`) ;
  3. **la ligne « Page »** n'est écrite que là où le journal des requêtes est gardé (`vars.JOURNAL_DES_PAGES`, voir la 0037) ;
  4. **relevé quotidien** : en production, « journal coupé » pour la répartition par page (coupures et temps de calcul viennent toujours des statistiques, inchangés) ; en préprod, chaque coupure est nommée par l'événement de requête lui-même (`$workers.outcome`, `$workers.event.request.path` ramené au modèle de la page), la ligne « Page » en appoint ;
  5. **un nouveau centre aux données réelles** copie le réglage de `centres/laille` : tout coupé par défaut ([installer-un-centre.md](../technique/installer-un-centre.md)).
- **Vérifié dans la documentation de Cloudflare** (15/11/2026) et avec Wrangler 4.152.0, celui du dépôt :
  - **clés acceptées** : Wrangler accepte `observability.traces { enabled, head_sampling_rate, persist }`, `observability.issues { enabled }` (Wrangler 4.134.0 et plus) et `observability.redact_query_string` ([configuration Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/), schéma de Wrangler). Le tableau de bord dit `issue_detection`, mais la clé de Wrangler est **`issues`** : `issue_detection` est refusé (« Unexpected fields found in observability field »). `wrangler deploy --dry-run` passe sans avertissement sur les deux configs ;
  - **traces** : coupées par défaut, `observability.enabled` ne les active pas ; gardées 7 jours ([Traces](https://developers.cloudflare.com/workers/observability/traces/)) ;
  - **détection des problèmes (Issues)** : regroupe les exceptions, invocations en échec, réponses 5xx et erreurs écrites ; ouverte à tous les comptes, **gratuite pendant la bêta** ([Issues](https://developers.cloudflare.com/workers/observability/issues/)) ;
  - **coût sur l'offre gratuite** : rien avant le 1er décembre 2026 ; ensuite, journal, traces et Issues partagent **0,5 Go par jour**, gardés 7 jours, sans dépassement possible : au-delà, Cloudflare n'enregistre plus rien jusqu'à minuit UTC, **sans rien facturer** ([tarifs Observability](https://developers.cloudflare.com/observability/pricing/)). La préprod fait quelques centaines de requêtes par jour : très loin de la limite. Pas payant : les deux parties sont activées ;
  - **`redact_query_string`** : non activé. En préprod (données fictives), les paramètres servent à lire une coupure ; en production, tout est coupé.
- **Validé par** : le porteur, le 15/11/2026 (production : choix (a), préprod avec traces et Issues) ; le détail, dans la PR.
