# 0025 — Le droit « Gérer l'habillement » et la reconstruction des tables de droits

- **Contexte** : l'habillement demande de savoir qui traite les demandes de tenue. Il n'existait ni rôle ni droit pour cela. La liste des droits (`DROITS`) est figée en base par une contrainte `CHECK` dans `profil_droit` et `responsabilite_droit`, et SQLite ne sait pas modifier une contrainte : ajouter un droit oblige à **reconstruire** ces deux tables, ce que le projet n'avait jamais fait sur des données réelles.
- **Options** : (1) se passer de droit, en reconnaissant le rôle par son nom ou son modèle ; (2) un vrai droit `GERER_HABILLEMENT`, comme `GERER_STOCK`, avec reconstruction ; (3) retirer le `CHECK` (la liste ne serait plus vérifiée par la base).
- **Choix** : (2). `GERER_HABILLEMENT` paraît dans Réglages (domaine « Habillement » des paquets), dans « Ce que ce rôle permet », et peut être donné à n'importe quel rôle. Le modèle et le rôle « Référent habillement » le portent ; le chef de centre et l'adjoint le tiennent, verrouillé, pour qu'une demande ne reste jamais bloquée.
- **La migration `0022`** : pour chaque table, nouvelle table (même colonnes, clés, `CHECK`, clé étrangère, avec la liste complétée), copie de toutes les lignes **avec leur `rowid`**, suppression de l'ancienne, renommage. Générée par drizzle-kit 0.31.11, puis retouchée à la main : drizzle-kit entoure la première table de `PRAGMA foreign_keys=OFF/ON` ; D1 applique toujours les clés étrangères et ignore ce réglage dans sa transaction (doc D1, « Define foreign keys ») — inutile ici, car aucune table ne pointe vers ces deux-là : supprimer et renommer ne viole rien. `wrangler d1 migrations apply` envoie le fichier entier en une requête (distant) ou un `batch` (local) : tout ou rien. Puis, en insertions gardées : le droit aux chefs et le rôle « Référent habillement » pour les bases déjà remplies.
- **Preuve** : `packages/socle/test/migration-0022.test.ts` joue la migration comme D1 (clés étrangères actives, une transaction) sur des droits variés (profils, tous les périmètres, rôles système ou non, verrouillés, avec trous dans les `rowid`) et compare toutes les lignes, colonnes, clés, index et définitions avant et après. Sans la recopie du `rowid`, le test échoue : drizzle-kit seul renumérotait les lignes.
- **Pour la suite** : chaque nouveau droit suivra ce chemin (voir [socle.md](../technique/socle.md), « Migrations »). Avant de l'appliquer sur une base réelle, noter le point de retour de D1 (`wrangler d1 time-travel info`) ; le déploiement applique déjà les migrations avant de publier le Worker.
- **Validé par** : le porteur, le 8 novembre 2026 (droit et reconstruction acceptés dans la spec).
