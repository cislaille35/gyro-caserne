# Échanges, lot 1 : les murs — plan de mise en œuvre

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Quatre sortes de murs (Le centre, Vie du centre, équipes, comités) avec publications (message, annonce, événement, bravo, sondage, photos), interactions, et « À ne pas manquer » sur l'accueil.

**Architecture:** Un mur est identifié par une **clé** (`centre`, `vie`, `equipe:<id>`, `comite:<id>`) ; ses droits se **déduisent de l'appartenance** au moment de la lecture (pas de ligne de droit à synchroniser). Le socle porte les tables (migration 0003, nouvelles tables seulement), les règles et les lectures groupées ; l'appli affiche l'onglet Échanges, les formulaires et « À ne pas manquer ». Photos réduites dans le navigateur, rangées en base (BLOB).

**Tech Stack:** SvelteKit 3, Svelte 5, Drizzle (D1 / SQLite en test), Vitest, Playwright + axe (CI).

**Spec:** `docs/superpowers/specs/2026-10-28-murs-design.md`

## Global Constraints

- Migration **additive** : nouvelles tables seulement ; aucune donnée existante transformée.
- **≤ 45 requêtes** par page ou action (test de budget existant `apps/web/src/routes/budget.test.ts` à étendre) ; un `batch` = 1 ; jamais deux colonnes de même nom issues de tables jointes dans un même `batch` (D1).
- Droits de départ (tableau de la spec) : Le centre — lire : agents ; publier, modérer, épingler : chef de centre, adjoint. Vie du centre — lire, publier : agents ; modérer : chef, adjoint. Équipe N — lire, publier : membres en cours et chef d'équipe ; modérer : chef d'équipe. Comité — lire, publier : membres et rapporteur en cours ; modérer : rapporteur. Chef de centre, adjoint et super administrateur lisent et modèrent tous les murs. Extérieurs : aucun mur. Agents partis ou suspendus : aucun. Mur d'équipe inactive ou de comité dissous : lecture seule.
- « Agent » = personne non partie, non suspendue, de profil de type agent (pas extérieur).
- Types : `message`, `annonce`, `evenement`, `bravo`. Annonce avec prise de connaissance : modérateurs seulement. Sondage : 2 à 6 réponses, un choix par personne. Événement : début (date + heure), lieu, convoqués (`tous` ou liste d'équipes), réponse `present` / `absent` / `incertain`.
- Photos : 4 au plus, JPEG ou WebP, **400 Ko au plus chacune** côté serveur ; réduction dans le navigateur (côté long 1600 px, qualité ≈ 0,8). Servies seulement à qui peut lire le mur ; jamais d'adresse publique.
- Anniversaires : agents non partis avec une date de naissance et `anniversaireVisible` à 1 ; jour et mois de Paris ; jamais l'âge.
- Fondations : `#lib/ui`, téléphone d'abord, RGAA AA, vouvoiement, pas de fausses données. Machine 2 Go : cage, commit + push à chaque étape verte, Playwright en CI.

## Review Focus

1. Un agent qui change l'adresse (`/echanges/equipe:3` d'une autre équipe, `/echanges/photo/<id>` d'un mur non lisible, action sur une publication d'un autre mur) → 403, rien d'écrit ni de lu (Tâches 1, 2, 5).
2. Un agent qui quitte une équipe ou un comité, passe parti ou suspendu → n'a plus accès dès le jour même (Tâche 1).
3. Une annonce avec prise de connaissance publiée dans « Le centre » apparaît dans « À ne pas manquer » de chaque agent jusqu'à ce qu'il clique, et l'auteur voit la liste exacte de qui manque (Tâches 3, 4).
4. Photo trop lourde, mauvais type, cinq photos, photo envoyée à une publication d'un autre auteur → refus clair (Tâche 2).
5. Mur de 300 publications et 150 agents : page du mur et accueil ≤ 45 requêtes, pagination (Tâches 2, 4).

### Tâche 1 : Socle — tables et droits des murs

**Files:** `packages/socle/src/schema.ts` + migration générée, Create `packages/socle/src/murs.ts`, tests `packages/socle/test/murs.test.ts`, `index.ts`

**Interfaces (produces):**
- Tables : `publication` (id, mur text, auteur text « personne:<id> » ou « super:<email> », type, texte, prise_de_connaissance int, epinglee int, commentaires_fermes int, cree_le, modifiee_le, debut, lieu, convoques text JSON, sondage_question, sondage_reponses text JSON), `commentaire` (id, publication_id, auteur, texte, cree_le), `jaime` (publication_id, personne_id, PK double), `reponse_evenement` (publication_id, personne_id, reponse), `vote_sondage` (publication_id, personne_id, reponse int), `prise_connaissance` (publication_id, personne_id, le), `photo_publication` (id, publication_id, ordre, type, donnees blob), `visite_mur` (personne_id, mur, vue_le). Clés étrangères vers `publication` avec suppression en cascade.
- `export type CleMur = 'centre' | 'vie' | \`equipe:${number}\` | \`comite:${number}\``
- `export type Mur = { cle: CleMur; nom: string; type: 'centre' | 'vie' | 'equipe' | 'comite'; peutPublier: boolean; peutModerer: boolean; lectureSeule: boolean }`
- `mursDe(base, acteur, aujourdhui): Promise<Mur[]>` — dans l'ordre : Le centre, Vie du centre, ses équipes, ses comités ; chef, adjoint et super : tous les murs (équipes actives et comités non dissous, plus les inactifs/dissous en lecture seule).
- `exigerMur(base, acteur, cle, aujourdhui, besoin: 'lire' | 'publier' | 'moderer'): Promise<Mur>` — `RefusDroit` sinon ; clé mal formée → `DonneeInvalide('Mur inconnu')`.

- [ ] **Step 1 : tests qui échouent** : chaque ligne du tableau des droits (agent, chef d'équipe, membre et rapporteur de comité, chef, adjoint, super, extérieur, parti, suspendu) ; affectation terminée hier → plus d'accès ; équipe inactive et comité dissous → lecture seule (publier refusé) ; clé `equipe:abc` → « Mur inconnu » ; ≤ 10 requêtes pour `mursDe` d'un chef de centre ; migration : seules des `CREATE TABLE`/`CREATE INDEX`.
- [ ] **Step 2–4** : échecs, implémenter, tests + `tsc` en cage. **Step 5** : commit `Socle : tables et droits des murs`, push, PR brouillon.

### Tâche 2 : Socle — publications et photos

**Files:** Create `packages/socle/src/actions/publications.ts`, tests, `index.ts`

**Interfaces:**
- Consumes : Tâche 1.
- Produces :
  - `publier(base, acteur, cle, donnees: { type; texte; priseDeConnaissance?: boolean; evenement?: { debut: string; lieu: string; convoques: 'tous' | number[] }; sondage?: { question: string; reponses: string[] }; photos?: { type: string; donnees: Uint8Array }[] }, maintenant: string): Promise<number>` — un seul `batch` (publication, photos, journal `publier` sans le texte) ;
  - `modifierPublication(…, id, { texte }, maintenant)` (auteur), `supprimerPublication(…, id, maintenant)` (auteur ou modérateur ; photos et dépendances supprimées ; journal sans contenu), `epingler(…, id, oui: boolean)` et `fermerCommentaires(…, id, oui: boolean)` (modérateur ; fermer : aussi l'auteur) ;
  - `lireMur(base, acteur, cle, { avant?: number; nombre?: number = 20 }, aujourdhui): Promise<{ mur: Mur; epinglees: PublicationVue[]; publications: PublicationVue[]; suite: number | null }>` avec `PublicationVue` = auteur (prénom, nom), type, texte, dates, `photos: number[]` (ids), compteurs (j'aime, commentaires), « j'aime » de l'acteur, événement (+ réponse de l'acteur et compte par réponse), sondage (+ vote de l'acteur et résultats), prise de connaissance (+ faite par l'acteur), droits de l'acteur sur la publication ; marque la visite du mur (`visite_mur`) ;
  - `photo(base, acteur, idPhoto, aujourdhui): Promise<{ type: string; donnees: Uint8Array }>` — après `exigerMur(… 'lire')`.
- Règles : texte 1 à 4 000 caractères ; titre de sondage 1 à 200, réponses 1 à 100 ; photos selon les contraintes globales ; convoqués d'un mur d'équipe = cette équipe ; annonce avec prise de connaissance réservée aux modérateurs ; type `evenement` exige `debut` futur ou du jour.

- [ ] **Step 1 : tests qui échouent** : chaque règle ci-dessus ; publication puis lecture (épinglées en tête, ordre décroissant, pagination 20 + `suite`) ; suppression par modérateur, refus pour un autre agent ; photo d'un mur non lisible → `RefusDroit` ; photo > 400 Ko, type PNG, 5 photos → refus ; mur de 300 publications : `lireMur` ≤ 12 requêtes.
- [ ] **Step 2–4** : échecs, implémenter, tests + `tsc` en cage. **Step 5** : commit `Socle : publications et photos des murs`, push.
