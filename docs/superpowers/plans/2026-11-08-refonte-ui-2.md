# Refonte UI, deuxième passe : plan

> **Pour les exécutants :** suivre `superpowers:executing-plans` ou `superpowers:subagent-driven-development`, tâche par tâche. Cases `- [ ]` à cocher.

**But :** la direction B sur tous les écrans, une seule version de chaque composant, puis la charte.

**Méthode :** chaque lot part de `fonction/refonte-ui` sur une branche `refonte/<lot>`, avec sa PR vers `fonction/refonte-ui`. Le test d'abord, puis le code. Une review par lot, la CI complète une fois, puis squash par Claude.

**Technique :** SvelteKit 5, CSS par jetons dans `apps/web/src/app.css`, vitest, Playwright et axe en CI seulement.

**Spec :** [`design.md`](../specs/2026-11-08-refonte-ui-2/design.md), à lire avec ce plan. Défauts à traiter : [téléphone](../specs/2026-11-08-refonte-ui-2/inventaire-tel.md), [ordinateur](../specs/2026-11-08-refonte-ui-2/inventaire-ordi.md).

## Contraintes pour toutes les tâches

- Aucune migration, aucune nouvelle dépendance, aucune information ni action perdue.
- Couleurs, rayons, espacements et courbes par jetons. Composants communs d'abord.
- RGAA AA, clavier, mode contrasté, « réduire les animations » : aucun test affaibli sur le fond. Un test qui fixe l'ancien habillage change avec le code.
- Chaque ligne d'inventaire est vérifiée à l'écran avant correction. Une ligne fausse est écartée et dite dans le compte rendu.
- En local : `pnpm --filter @gyro-caserne/web test` et `check`, en cage mémoire et avec une limite de temps. Node 24 : `~/.local/lib/node-v24.22.1-linux-x64/bin`.
- Captures par lot : écrans principaux seulement, téléphone en clair, ordinateur en sombre, après chargement complet et avec `locale: 'fr-FR'`.
- Chaque PR tient à jour `docs/technique/interface.md` et, si un comportement change, `docs/fonctionnel/` et `docs/utilisation/`.

## À surveiller en review

- Mode contrasté : une carte plate garde son bord transparent, une icône sans tuile reste visible.
- Couleur d'équipe claire ou sombre : une bande retirée laisse le carré de couleur et le nom, le texte reste choisi par `encreSur`.
- Thème `auto` : il reste identique au thème sombre (`jetons.test.ts`).
- Noms longs et texte agrandi à 200 % : pas de débord une fois les boutons regroupés.
- Sans JavaScript : un panneau, un menu d'actions ou un champ fichier dessiné reste utilisable.
